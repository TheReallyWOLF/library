## Что такое ООП
### Краткое описание:
    Объектно-ориентированное программирование (ООП) — это парадигма программирования, основанная на концепции "объектов", 
    которые представляют собой как данные, так и методы, действующие на этих данных. ООП позволяет моделировать сложные системы, 
    делая код более организованным, модульным и повторно используемым.

### Полное описание:
    ООП основывается на нескольких ключевых концепциях, таких как объекты, классы, наследование, инкапсуляция и полиморфизм.
    В этой парадигме объекты могут быть созданы из классов, которые описывают их свойства (атрибуты) и поведение (методы). 
    Это делает программы более структурированными, облегчает работу с кодом и позволяет разработчикам легче поддерживать и 
    расширять приложения.

### Принципы ООП:

#### Базовые понятия
    1. Объект (Object): Это экземпляр класса, который содержит состояние (данные) и поведение (методы).
    2. Класс (Class): Базовый шаблон для создания объектов, который определяет их свойства и методы.
#### Принципы
    Абстракция (Abstraction):
        Фокус на выделении основных характеристик объекта, игнорируя детали реализации. 
        Абстракция позволяет создавать абстрактные классы или интерфейсы, определяющие поведение без конкретных деталей. 
        Пример: Класс "Транспортное средство" имеет метод "двигаться", но не уточняет механизм (на колёсах или гусеницах).

    Инкапсуляция (Encapsulation):
        Скрытие внутренней реализации объекта от внешнего мира, с предоставлением доступа только через публичные методы. 
        Это защищает данные от несанкционированного изменения и упрощает модификацию кода. 
        Пример: В классе "Банк" баланс — приватное поле, доступ к которому осуществляется через методы "пополнить" и "снять".

    Наследование (Inheritance):
        Возможность создания новых классов на основе существующих, наследуя их свойства и методы. 
        Это способствует повторному использованию кода и созданию иерархий. Пример: Класс "Собака" наследует от "Животное" 
        методы "есть" и "спать", добавляя свои, как "лаять".

    Полиморфизм (Polymorphism):
        Возможность объектов разных классов отвечать на один и тот же вызов метода по-разному.
        Это достигается через перегрузку методов или интерфейсы. 
        Пример: Метод "рисовать" в классе "Фигура" реализуется по-разному в подклассах "Круг" (рисует окружность) и "Квадрат" 
        (рисует квадрат).

#### Академичекское (полное) описание полиморфизма

1. Ad Hoc Полиморфизм
   Описание: Один и тот же идентификатор (имя метода или оператора) ведет себя по-разному в зависимости от типов или количества аргументов. Реализуется через перегрузку (overloading) и часто решается на этапе компиляции.
   Связь с предыдущей классификацией: Соответствует статическому (compile-time) полиморфизму.
   ```java
   Пример (Java):
   public class Calculator {
      public int add(int a, int b) { return a + b; }
      public double add(double a, double b) { return a + b; }  // Перегрузка по типам
   }
   ```
   
   Вызов add(1, 2) выберет int-версию; add(1.0, 2.0) — double.
2. Параметрический Полиморфизм
   Описание: Код работает с любыми типами данных без их явного указания заранее. Реализуется через generics (дженерики) в языках вроде Java, C# или Haskell. Не зависит от наследования.
   Связь с предыдущей классификацией: Дополнительный вид, не строго ООП; упоминался как "параметрический" в предыдущем ответе.
   ```java
      Пример (Java):
      public class Box<T> {
         private T item;
         public void setItem(T item) { this.item = item; }
      }
   ```
   
   // Использование: Box<String> box = new Box<>(); box.setItem("Hello");
   Класс Box работает с любым типом T (String, Integer и т.д.) без переписывания кода.
3. Полиморфизм Подтипов
   Описание: Объекты подклассов могут заменять объекты суперкласса, и поведение определяется реальным типом объекта во время выполнения. Основан на наследовании и интерфейсах.
   Связь с предыдущей классификацией: Соответствует динамическому (runtime) полиморфизму.
   ```java
   Пример (Java):
   class Animal {
      public void sound() { System.out.println("Звук"); }
   }
   class Dog extends Animal {
   @Override
      public void sound() { System.out.println("Гав"); }  // Переопределение
   }
   ```
   
   // В коде: Animal a = new Dog(); a.sound();  // Выведет "Гав"
   Метод выбирается по типу объекта (Dog) во время выполнения.

## SOLID
SOLID это - принципы объектно-ориентированного программирования 
Single responsibility — принцип единственной ответственности
Open-closed — принцип открытости / закрытости
Liskov substitution — принцип подстановки Барбары Лисков
Interface segregation — принцип разделения интерфейса
Dependency inversion — принцип инверсии зависимостей

Принцип единственной обязанности / ответственности (single responsibility principle / SRP) обозначает,
что каждый объект должен иметь одну обязанность и эта обязанность должна быть полностью инкапсулирована в класс

Принцип открытости / закрытости (open-closed principle / OCP) декларирует, что программные сущности (классы, модули, функции и т. п.) должны быть открыты для расширения, но закрыты для изменения

Принцип подстановки «функции, которые используют базовый тип, должны иметь возможность использовать подтипы базового типа не зная об этом

Принцип разделения интерфейса «клиенты не должны зависеть от методов, которые они не используют»

Принцип инверсии зависимостей модули верхних уровней не должны зависеть от модулей нижних уровней

## принципы программирования

1. KISS
   Принцип «простоты» keep it simple, stupid

2. DRY
   Принцип „отсутствия повторов” don’t repeat yourself principle

3. Open/Closed
   Код должен быть открытым для внедрения новых областей, но закрытым для изменений

4. Принцип единой ответственности
   В принципе единой ответственности говорится, что каждый класс или модуль в программе должен заниматься только одним набором конкретных функций.

5. Разделение интересов
   Принцип разделения интересов – это принцип единой ответственности, но на более абстрактном уровне. По сути, программа должна быть спроектирована таким образом,
   чтобы она имела много разных не перекрывающихся инкапсуляций, и эти инкапсуляции не должны взаимодействовать друг с другом.

6. YAGNI
   Принцип основывается на том, что вам никогда не нужно реализовывать какую-либо функциональность,
   которая возможно вам понадобится в будущем. Скорее всего, вам это не понадобится, и это будет пустая трата времени, это также усложнит ваш код.

7. Избежание преждевременной оптимизации

8. Рефакторинг, рефакторинг и ещё раз рефакторинг

9. Чистый код много лучше >>> Умный код
