## Что такое патерны
В програмировании это концепция решения повторяющейся задачи. 

Паттерн — это проверенные временеи, стандартизированные решения для типичных задач или проблем, которые возникают при разработке. 
    Они представляют собой шаблоны, алгоритмы или "рецепты", описывающие, как организовать код, чтобы он был более эффективным, гибким, 
    поддерживаемым и повторно используемым. Паттерны не являются готовым кодом, они предлагают абстрактный подход.

## Три основные группы
1. Порождающие (Creational): Помогают управлять созданием объектов, обеспечивая гибкость.
    - Примеры:
        + Singleton: Гарантирует, что у класса есть только один экземпляр (например, для глобального конфига).
        + Factory Method: Создаёт объекты через интерфейс, скрывая логику создания (полезно для Angular сервисов).
        + Builder: Постепенно строит сложные объекты (например, для форм с динамическими полями).

2. Структурные (Structural): Определяют, как взаимодействуют классы и объекты, формируя более крупные структуры.
    - Примеры:
        + Adapter: Адаптирует интерфейс одного класса к другому (например, для интеграции сторонних библиотек).
        + Decorator: Динамически добавляет поведение объекту (как в Angular для директив).
        + Composite: Представляет иерархию объектов как единое целое (например, для деревовидных структур UI).

3. Порождающие (Creational): Помогают управлять созданием объектов, обеспечивая гибкость.
    - Примеры:
        + Observer: Реализует подписку на изменения (широко используется в RxJS в Angular для обработки событий, обсерваблов).
        + Strategy: Позволяет выбирать алгоритм во время выполнения (например, для разных методов валидации).
        + Command: Инкапсулирует запрос как объект, позволяя откладывать выполнение (полезно для очередей задач).

## Примеры патернов

1. Abstract Factory [Порождающий] - Создает семейства связанных объектов без указания конкретных классов, полезно для фабрики компонентов в Angular.
2. Builder [Порождающий] - Постепенно строит сложные объекты (например, конфигурация форм или маршрутов в Angular).
3. Factory Method [Порождающий] - Определяет интерфейс для создания объектов, скрывая логику; часто используется в Angular для динамических сервисов.
4. Prototype [Порождающий] - Позволяет создавать копии объектов; применяется в Angular для клонирования состояний в формах.
5. Singleton [Порождающий] - Гарантирует один экземпляр класса; как в корневых сервисах Angular (Root Injector).
6. Adapter [Структурный] - Адаптирует интерфейсы; например, для интеграции сторонних API в Angular-приложения.
7. Bridge [Структурный] - Разделяет абстракцию от реализации; полезно в Angular для разных платформ (web/mobile).
8. Composite [Структурный] - Представляет объект как древовидную структуру; идеально для иерархий компонентов в Angular (родительские/дочерние компоненты).
9. Decorator [Структурный] - Динамически добавляет поведение; реализовано в Angular через директивы и декораторы классов.
10. Facade [Структурный] - Предоставляет унифицированный интерфейс для сложных подсистем; упрощает работу с Angular-сервисами.
11. Flyweight [Структурный] - Оптимизирует память, разделяя общие объекты; применяется в Angular для повторяющихся шаблонов компонентов.
12. Proxy [Структурный] - Контролирует доступ к объекту; используется в Angular для ленивой загрузки или кеширования HTTP-запросов.
13. Chain of Responsibility [Поведенческий] - Передает запрос по цепочке обработчиков; можно реализовать в Angular для middleware посредников в маршрутизации.
14. Command [Поведенческий] - Инкапсулирует запрос как объект; полезно в Angular для асинхронных операций через Action/Reducer (NgRx).
15. Interpreter [Поведенческий] - Определяет представление грамматики; редко, но применимо для парсинга выражений в Angular-формах.
16. Iterator [Поведенческий] - Предоставляет последовательный доступ к элементам коллекции; встроено в Angular через *ngFor для итераций.
17. Mediator [Поведенческий] - Координирует взаимодействие между объектами; повышает слабо связанность компонентов в Angular.
18. Memento [Поведенческий] - Сохраняет и восстанавливает состояние объекта; используется в Angular для undo/redo в формах.
19. Observer [Поведенческий] - Реализует подписку на изменения; основа RxJS в Angular для обсерваблов и событий изменения данных.
20. State [Поведенческий] - Позволяет объекту изменять поведение при смене состояния; применяется в Angular для динамических UI-состояний.
21. Strategy [Поведенческий] - Определяет семейство алгоритмов; как в Angular для выбора разных валидаторов форм (например, кастомные вместо Validators.min).
22. Template Method [Поведенческий] - Определяет skeleton алгоритма; полезно в Angular для жизненных циклов компонентов (ngOnInit и т.д.).
23. Visitor [Поведенческий] - Добавляет операции к объектам без изменения их классов; расширяет функциональность компонентов в Angular.
24. MVC [Архитектурный] - Model-View-Controller; базовая структура Angular приложения (компоненты как View/Controller, сервисы как Model).
25. MVP [Архитектурный] - Model-View-Presenter; вариант для более слабой связанности в Angular с презентерами-сервисами.
26. MVVM [Архитектурный] - Model-View-ViewModel; стандарт в Angular с ViewModel в виде компонентов и data-binding.
27. Component-Based [Архитектурный] - Структура на основе компонентов; основа Angular, где приложение строится из модульных блоков.
28. Microservices [Архитектурный] - Разделение на небольшие сервисы; применяется в больших Angular-приложениях с бэкендом microservices.
29. Layered Architecture [Архитектурный] - Разделение на слои (presentation, business, data); отражено в Angular через UI, сервисы и HTTP-слои.
30. Repository [Архитектурный] - Абстрагирует доступ к данным; используется в Angular для сервисов, управляющих данными из API.
31. Unit of Work [Архитектурный] - Координирует операции с данными как единицу; полезно в Angular для транзакций изменений состояний.
32. Saga [Архитектурный] - Управляет долгоживущими транзакциями; применяется в RxJS для последовательных асинхронных операций в Angular.
33. Event Sourcing [Архитектурный] - Сохраняет состояния как последовательность событий; реализуемо в Angular с NgRx для истории состояний.
34. CQRS [Архитектурный] - Command Query Responsibility Segregation; разделяет чтение/запись, как в сложных Angular-формах с отдельными сервисами.
35. Dependency Injection [Архитектурный] - Инвертирует контроль создания зависимостей; ключевой механизм в Angular через Injector.
36. Lazy Loading [Архитектурный] - Загружает модули по требованию; встроено в Angular routing для улучшения производительности.
37. Module Pattern [Архитектурный] - Организует код в модули; основа NgModules в Angular для инкапсуляции и повторного использования.
38. Observer Pattern in RxJS [Реактивный] - Расширение Observer для потоков данных; фундамент Angular для управления асинхронностью.
39. Subject [Реактивный] - Многоадресный Observable; используется в Angular для глобальных подписок на события.
40. Operator Chain [Реактивный] - Цепочки операторов для обработки потоков; как map, filter в RxJS для Angular HTTP-запросов.
41. Hot Observable [Реактивный] - Производит данные независимо от подписчиков; применяется в Angular для таймеров и глобальных событий.
42. Cold Observable [Реактивный] - Производит данные по запросу; стандарт для API-запросов в Angular.
43. Monad [Функциональный] - Широко используется в RxJS как Observable для цепочек операций в Angular.
44. Functor [Функциональный] - Позволяет применение функций к содержащимся значениям; в RxJS map для трансформации данных.
45. Reducer [Функциональный] - Агрегирует значения в одно; как в NgRx reducers для управления состоянием в Angular.
46. Currying [Функциональный] - Преобразует функцию в цепочку; полезно для конфигурации Angular-пайпов.
47. Partial Application [Функциональный] - Фиксирует части аргументов; применяется в Angular для фабрик сервисов.
48. Compose [Функциональный] - Составляет функции в цепочку; как в Angular для комбинации валидаторов.
49. Pipe [Функциональный] - Аналог compose; RxJS pipe в Angular для многошаговой обработки.
50. DAO [Предпринимательский] - Data Access Object; абстракция для доступа к данным в Angular-сервисах.
51. DTO [Предпринимательский] - Data Transfer Object; упрощает передачу данных между слоями в Angular API-интеграциях.
52. Singleton Service [Предпринимательский] - Обеспечивает глобальный доступ; как root сервисы в Angular.
53. Factory for Entities [Предпринимательский] - Создает бизнес-объекты; расширяет Factory Method в Angular для моделей.
54. Repository Pattern [Предпринимательский] - Управляет коллекциями объектов; как в Angular с HttpClient для CRUD.
55. Specification [Предпринимательский] - Определяет критерий для объектов; полезно для фильтров в Angular-списках.
56. Value Object [Предпринимательский] - Неизменяемые объекты значений; как в Immutable.js для состояний в Angular.
57. Composite UI [UI] - Организует UI как древовидную структуру; родственно Composite в Angular-шаблонах.
58. Master-Detail [UI] - Показывает мастер-список и детали; часто реализуемо в Angular маршрутами и компонентами.
59. Modal Dialog [UI] - Управляет диалоговыми окнами; через MatDialog в Angular Material.
60. Infinite Scroll [UI] - Загружает контент по мере прокрутки; используется в Angular для больших списков.
61. Accordion [UI] - Сворачиваемые секции; компоненты в Angular с *ngIf для показа/скрытия.
62. Breadcrumb [UI] - Навигационная цепочка; реализуемо через ActivatedRoute в Angular.
63. Null Object [Другие] - Избегать null проверок; паттерн-"пустышка" для безопасных по умолчанию значений в Angular.
64. Exception Handling [Другие] - Перехват и обработка ошибок; как в Angular через HttpInterceptor для глобального управления ошибками.
