## Обработка ошибок рендеринга

Error Boundary — это механизм в React для обработки и локализации ошибок JavaScript, возникающих в процессе рендеринга компонентов.
Это предотвращает "падение" всего приложения из-за одной ошибки в компоненте. Вместо краха приложения отображается запасной (fallback) пользовательский интерфейс.
Error Boundary работает только для синхронных ошибок в рендере, не для асинхронных (например, в setTimeout или событиях).

В ванильном JavaScript (без React) ошибок рендеринга нет — там используются try-catch для блоков кода.
Но в React это концепция, реализованная через специальные компоненты-классы.
Код будет на чистом JavaScript (не TypeScript), но в реальном проекте часто используется с JSX/TSX. Предполагаю React-фреймворк.

### Зачем нужны Error Boundary
Без них одна ошибка (например, null reference в шаблоне) вызывает "красный экран" или полный крах приложения. С ними:

Локализация: Ошибка изолируется, не затрагивая остальные компоненты.
Устойчивость: Приложение продолжает работать с fallback-UI.
Логирование: Можно собирать ошибки для отладки (отправлять в сервисы вроде Sentry).
Пользовательский опыт: Показывается понятное сообщение вместо технических деталей.
Ограничения: Не ловят ошибки в event handlers, async коде, серверном рендеринге или самих Error Boundary.
